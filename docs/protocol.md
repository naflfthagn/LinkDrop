# LinkDrop 局域网互传协议 v1

LinkDrop 的 Windows 端与 Android 端使用同一套轻量点对点协议。协议运行在局域网 TCP 连接上，外层使用 TLS 1.2 加密；PC 作为 TLS 服务端，手机作为 TLS 客户端。

## 发现

- UDP 组播组：`239.255.47.22:48721`（同时向 `255.255.255.255:48721` 广播）
- PC 每 2 秒发送一次信标：

```json
{"m":"QCLINK1","v":1,"kind":"beacon","id":"0123456789abcdef","name":"DESKTOP-PC","platform":"windows","port":48622,"pairing":false}
```

`id` 是 PC 证书 SHA-256 指纹的前 16 个十六进制字符；`port` 是实际 TCP 监听端口（默认 48622，占用时递增至 48632）。

## TLS 与配对

1. PC 生成并持久化一张自签名 RSA-2048 证书；私钥只保存在本机。
2. 手机首次配对时连接 PC 的 TLS 端口，读取服务端证书并计算安全码：证书 DER 的 SHA-256 前 4 字节按无符号大端整数对 1,000,000 取模，格式化为 6 位数字。
3. PC 端在配对模式中显示同一个安全码，并由用户核对、明确允许。手机根据 PC 是否处于配对模式提示用户。
4. 配对成功后 PC 生成 256 位随机令牌，经 TLS 返回手机；两端分别保存令牌与证书指纹。
5. 之后手机自动发现 PC、校验固定证书指纹，并携带令牌完成握手。任何一方没有配对记录时都不能传文件。

## 帧格式

每条消息为：

```
4 字节大端无符号长度 N
1 字节类型：0x01=JSON 控制帧，0x02=二进制文件块
N 字节负载
```

JSON 为 UTF-8。二进制帧负载为：

```
8 字节大端有符号传输 ID | 4 字节大端无符号块长度 | 块数据
```

单帧上限 4 MiB，文件块长度 256 KiB。

## 控制消息

| op | 方向 | 说明 |
| --- | --- | --- |
| `hello` | 手机 → PC | 携带协议版本、设备信息、配对令牌 |
| `welcome` | PC → 手机 | 鉴权成功 |
| `error` | 双向 | 错误代码与说明 |
| `pair_request` | 手机 → PC | 请求配对（仅在 PC 配对模式内有效） |
| `pair_pending` | PC → 手机 | 配对请求已送达，等待 PC 用户确认 |
| `pair_result` | PC → 手机 | `ok`、`token`、服务端设备信息或错误 |
| `offer` | 双向 | 文件提议：`id`（十进制字符串）、`name`、`size`、`mime` |
| `accept` / `reject` | 接收方 | 对文件提议的响应 |
| `done` | 发送方 | 文件发完，携带 SHA-256 |
| `complete` / `fail` | 接收方 | 校验并落盘成功 / 失败 |
| `ping` / `pong` | 双向 | 保活 |

## 文件传输

1. 发送方发送 `offer`，等待 `accept`（手机和 PC 在已鉴权连接上自动接受）。
2. 发送方读取文件、计算 SHA-256，并循环发送二进制块。
3. 发送方发送 `done` 与摘要；接收方先写临时文件，校验大小与摘要后原子发布到下载目录，并返回 `complete` 或 `fail`。
4. 两端同时双向传输；写入通过锁串行化，读取循环独立。
